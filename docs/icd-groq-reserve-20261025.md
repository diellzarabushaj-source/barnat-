# ICD description search: Groq reserve

Gemini remains the primary provider. ICD search tries the distinct existing `GEMINI_API_KEY`, `GEMINI_API_KEY1` and `GEMINI_API_KEY2` credentials in order, once each, skipping credentials in a short capacity cooldown. All Gemini attempts share an 18-second deadline. After explicit per-query consent naming both recipients, anonymous descriptions may then go to Groq when no Gemini credential is available. The server uses `openai/gpt-oss-120b` at Groq's fixed chat-completions endpoint, with strict JSON, low reasoning effort, a 1,800-token completion cap and a 15-second reserve deadline. The overall description deadline remains 45 seconds. No paid plan, additional dependency, database migration or prescription-provider change is included.

Activation requires server-only `GROQ_API_KEY` and `ICD_GROQ_FALLBACK_ENABLED=true`. Production alone is configured; Preview and Development do not receive the credential. The key is saved as a Vercel Secret. Its value is absent from source, tests, documentation and browser bundles. The frontend sends `groqFallback: true` only for the confirmed description action. Existing clients without that flag retain Gemini-only behavior; cache entries are separated by recipient consent as well as signed owner and classification.

Quota failures open a short, function-instance cooldown per credential fingerprint; duplicate values are deduplicated and the values are never logged. Upstream credential denials (401/403) or payment-required responses (402) skip that credential for five minutes and use the next already configured option, including Groq only after recipient consent. This does not bypass application authentication: signed ownership, CSRF and budgets are enforced before routing. No billing/access changes, new quota-bypass keys, repeated Groq attempts or paid-provider escalation occur. Google quotas are per project, so keys belonging to the same project cannot provide extra project quota. `Retry-After` is bounded. Groq failures never expose remote response bodies. Cached responses retain the actual provider label. Normal catalog search stays available without either provider.

Both providers pass through the same canonical WHO ICD-10 2019 validation, escaped explanation rendering and clinical safeguards. Results remain unconfirmed retrieval suggestions, with no automatic choice, definitive diagnosis, treatment advice or terminology/database write. Input privacy filtering is a guard rather than a comprehensive identifier detector; clinicians must anonymize descriptions before confirming transmission.

The free Groq plan has request and token limits, which may change. This feature improves availability but cannot promise unlimited use or diagnostic accuracy. No payment or upgrade was activated.

Validation covers quota/capacity fallback, cooldown, cancellation, authentication denial, explicit recipient consent, old-client isolation, strict schema, canonical codes, incomplete JSON, safe errors, owner/consent cache separation, accurate live/cache labels and phone/desktop layouts. Controlled fixtures verify software behavior; production provider results are recorded separately.

Official references: [Groq structured output](https://console.groq.com/docs/structured-outputs), [model](https://console.groq.com/docs/model/openai/gpt-oss-120b), [API](https://console.groq.com/docs/api-reference), [rate limits](https://console.groq.com/docs/rate-limits), [data handling](https://console.groq.com/docs/your-data).

The first production smoke reached Groq in 2.4 seconds but exposed invalid clinical code/concept pairs despite valid catalog codes. The follow-up requires an exact canonical English title for each proposed code and rejects mismatches or missing titles. Model text never replaces the displayed catalog title. Pain-only retrieval hints are no longer injected for every symptom. The prompt distinguishes haematemesis (K92.0) from haemoptysis (R04.2), avoids unsupported bleeding causes and recognizes haematemesis as a symptom outside chapter R. The response-cache namespace changes so earlier unbound results cannot be reused. These are stronger software checks, not proof of general clinical accuracy.

Classification references: [NHS tabular K92.0](https://classbrowser.nhs.uk/ICD-10-5TH-Edition/vol1/block-k90-k93.htm), [NHS tabular R04.2](https://classbrowser.nhs.uk/ICD-10-5TH-Edition/vol1/block-r00-r09.htm).

Credential failover respects the [Gemini project-level rate-limit model](https://ai.google.dev/gemini-api/docs/rate-limits); merely adding keys to one project does not increase its allowance. Existing signed ownership, request budgets and consent gates apply before every provider attempt.
