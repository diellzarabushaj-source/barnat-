# Gemini interpretation of anonymous medical descriptions

The explicit ICD AI control now uses an `interpret` action through the existing signed, CSRF-protected clinical-editor endpoint. It sends an anonymous description to the existing Gemini transport, rather than requiring every input word to exist in the short terminology-alias whitelist. The ordinary search, alias writes, personal dictionary and administrator review retain their existing contracts.

Descriptions are limited to 600 characters/90 words. Explicit per-query confirmation remains required. Server-side checks reject common identifier labels, dates, email/URL/phone patterns and likely capitalized name pairs, and require medical vocabulary. These checks are not a comprehensive personal-data detector: the input must be anonymized by the clinician. The interface states this before transmission.

Gemini receives the WHO ICD-10 2019 classification, the description and bounded canonical catalog hints. It is instructed to respect anatomy, negation, radiation, timing and associated symptoms, return up to five ranked retrieval suggestions with short Albanian reasons, and ask a discriminating question when information is insufficient. It must not invent findings, provide treatment/doses, probabilities or a definitive diagnosis. This is search/clinical decision support, not proof of diagnostic accuracy.

Every returned code is validated against the active canonical WHO catalog; national-only codes, duplicate codes and invalid records are discarded. Titles and Latin remain catalog-owned. Disease candidates are allowed as explicitly unconfirmed differential suggestions; they are not silently converted into aliases for a symptom. No candidate is automatically selected. A clinician must explicitly choose a result.

The description action has no database-write path. Inferred suggestions are never submitted to the terminology-memory RPC. A bounded 10-minute function-instance cache is isolated by the signed owner and classification, with hashed description keys. In-flight calls coalesce and failures are evicted. Authentication/budget checks still run outside this cache. Existing fast fallback-model preference, low thinking, endpoint deadlines and 45-second overall model cancellation are reused; no new provider client, key, migration or dependency is added.

The reported regression was `dhimbje ne regjionin retroperitoneal`: `regjionin` was absent from the legacy whitelist, causing rejection before Gemini. The new description action accepts that anonymous clinical formulation and genuinely invokes Gemini. It does not force that wording into a hard-coded diagnosis. For location-only pain it requests clarification and conditional suggestions; more detailed descriptions may change their ranking.

Validation includes the screenshot phrase, a longer regional description, canonical-code and title preservation, invalid ICD-10-CM rejection, differential-only labels, no alias writes, explicit choice, owner isolation, coalescing, failed-cache recovery, consent/ownership binding, escaped model text, cancellation, offline/deadline recovery and existing phone/desktop search/dictionary/Recetat flows. Synthetic provider fixtures test software behavior; the production provider smoke result and latency are recorded separately after release.

Classification cross-checks: [WHO ICD-10 2019](https://icd.who.int/browse10/2019/en), [NHS abdominal-pain classification](https://classbrowser.nhs.uk/ICD-10-5TH-Edition/vol1/block-r10-r19.htm), [NHS dorsalgia classification](https://classbrowser.nhs.uk/ICD-10-5TH-Edition/vol1/block-m50-m54.htm). No fixed clinical mapping was added from these sources.
